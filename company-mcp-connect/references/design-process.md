## 1. 질문지

한 번에 2~3개씩 묻는다. 괄호 안은 권장 기본값 — 사용자가 모르면 이것으로 진행하고 그렇게 했다고 밝힌다.

### A. 시스템
- A-1. 업무 데이터가 들어 있는 DB 는 무엇인가? (PostgreSQL / MySQL·MariaDB / SQL Server / 모름)
  - 모르면: "회사 시스템을 만든 업체에 'DB 종류와 버전, 읽기 전용 계정을 만들 수 있는지'를 물어보세요"라고 적어 준다.
- A-2. DB 는 어디에 있나? (내 PC / 사무실 서버 / GCP Cloud SQL / AWS RDS / Azure / 업체가 관리)
  - 업체가 관리하는 SaaS 이고 DB 접근이 없으면 이 스킬의 대상이 아니다 → 그 SaaS 의 API·공식 커넥터를 찾는다.
- A-3. 업무 매뉴얼·규정·양식 같은 문서는 어디에 있나? (GCS / S3 / Azure Blob / 공유 폴더·NAS / 구글 드라이브 / 없음)
  - 구글 드라이브·노션은 공식 커넥터가 있으므로 그쪽을 권한다. 이 스킬의 저장소 어댑터는 버킷·폴더용이다.
  - 문서 형식이 .md·.txt 가 아니면(PDF·HWP·DOCX) 먼저 텍스트로 바꿔 두는 편이 낫다고 안내한다.

### B. 업무 질문 (가장 중요)
- B-1. "직원이 Claude 에게 실제로 물을 문장"을 5~10개 받는다. 사용자의 말투 그대로 적는다.
  - 예: "이번 주에 마감되는 거 뭐 있어?", "OO 고객 진행 중인 건 몇 개야?", "하자 접수되면 뭐부터 해?"
- B-2. 그 답을 지금은 사람이 어떻게 찾나? (어느 화면, 어느 엑셀) — DB 의 어느 표에 있는지 단서가 된다.

### C. 가릴 것
- C-1. 절대 AI 에게 보여 주면 안 되는 칸 (기본: 전화·이메일·주소·주민번호·계좌·급여)
- C-2. 조건부로 가릴 것 (예: 계약 전·출원 전 건의 이름, 특정 부서 자료)
- C-3. AI 가 보더라도 답에 그대로 옮기면 안 되는 것 (예: 내부 단가) — 이건 뷰에서 빼는 것이 확실하다.

### D. 쓰기
- D-1. 처음에는 읽기만으로 시작하자고 권한다. 그래도 필요한 쓰기가 있나?
- D-2. 있다면 딱 한 가지 동작으로 좁힌다 (예: "새 건 등록"만, "상태 변경"은 안 함).
- D-3. 그 쓰기는 두 번 실행되면 문제가 되나? (등록은 대개 그렇다 → 중복 방지 원장)

### E. 사람과 환경
- E-1. 누가 쓰나? (대표 혼자 / 팀 n명) — 팀이면 사람마다 접속 계정을 따로 두는 클라우드 IAM 이 기록자 증명에 유리하다.
- E-2. 어떤 PC 에서? (Windows / Mac) · 어떤 Claude? (Claude Code / Claude Desktop)
- E-3. 기술 담당자(사내 개발자·외주 업체)가 있나? — DB 쪽 SQL 실행을 누가 할지 정한다.

## 2. 도구 설계 원칙

1. **질문 하나 → 도구 하나가 아니라, 질문 묶음 → 도구 하나.** "이번 주 마감", "이번 달 마감", "지난 마감"은 `deadline_list(days, include_overdue)` 하나로.
2. **찾기 → 자세히 의 두 단계.** `*_search` 는 목록(코드·이름·상태)만, `*_detail` 은 한 건의 전부. Claude 가 검색 결과의 코드를 그대로 detail 에 넣게 description 에 적는다.
3. **만능 도구 금지.** `run_sql`, `read_any_file` 은 만들지 않는다. 가림·권한을 모두 무력화한다.
4. **입력은 좁게.** `enum` 으로 고를 수 있는 값은 enum, 개수는 `maximum`, 날짜는 형식 검사. `additionalProperties: false`.
5. **description 이 곧 사용 설명서.** Claude 는 이 글만 보고 도구를 고른다. 넣을 것:
   - 무엇을 돌려주는지 + **돌려주지 않는 것**("연락처는 돌려주지 않는다")
   - 실제 업무 질문 예시 1~2개(「이번 주 자재 발주 마감 뭐 있어?」)
   - 0건일 때 행동("없다고 답하고 지어내지 않는다")
   - 읽기 전용인지
6. **이름 앞머리.** `saebom_project_search` 처럼 회사 약칭을 붙인다. 다른 MCP 서버의 도구와 섞이지 않는다.
7. **번호 미리보기는 "예약 아님"을 밝힌다.** 다음 번호를 보여 주는 도구는 실제 등록 전까지 번호가 바뀔 수 있다고 적는다.
8. **쓰기 도구는 기본 목록에 없다.** `MCP_ENABLE_WRITES=1` 일 때만 나타나고, `confirm` 없이는 미리보기(예상 결과 + 비슷한 기존 건)만 돌려준다.
9. **문서(매뉴얼)는 찾기·읽기 두 개.** `manual_find(text)` 로 대목을 찾고 `manual_read(path)` 로 전문. 답할 때 문서 이름을 근거로 밝히게 한다.
10. **도구 수는 5~10개.** 넘으면 묶을 수 있는지 다시 본다.

## 3. 초안 양식

2단계에서 사용자에게 이 표로 보여 준다.

```
## 도구 목록 초안 — <회사명>

| # | 도구 이름 | 하는 일 | 답하는 업무 질문 | 읽는 곳(뷰/폴더) | 가림 | 읽기/쓰기 |
|---|---|---|---|---|---|---|
| 1 | xx_project_search | … | B-1 ①③ | mcp.v_project | 비공개 건 이름 | 읽기 |
| … |

### 업무 질문 → 도구 연결
- ① "이번 주 마감 뭐 있어?" → xx_deadline_list(days=7)
- ② …
- ⑦ "OO 고객 전화번호 알려줘" → 도구 없음(연락처는 열지 않기로 함) — Claude 는 사내 화면에서 확인하라고 안내

### 열지 않는 것
- 고객 연락처, 금액, 직원 급여 …
```

연결되지 않는 업무 질문이 있으면 "도구를 더할지, 일부러 열지 않을지"를 묻는다. 일부러 열지 않는 것도 결정으로 기록한다.

## 4. 가상 회사 예시 — 새봄인테리어

`templates/server/` 에 들어 있는 예시다(모든 데이터는 지어낸 것).

- 시스템: PostgreSQL(현장·고객·일정 표) + 로컬 폴더(시공 매뉴얼 .md)
- 업무 질문: "은행나무 빌라 현장 어디까지 했어?", "이번 주 자재 발주 마감 뭐 있어?", "욕실 방수 공사 순서가 어떻게 돼?", "푸른상사 진행 중인 현장 몇 개야?"
- 가림: 고객 전화·이메일·주소(뷰에 없음), 공사 금액(뷰에 없음), 계약 전 비공개 견적의 현장명(뷰에서 '(비공개 견적)'으로)
- 쓰기: 새 현장 견적 등록 하나만(기본 꺼짐)

| # | 도구 | 하는 일 | 읽는 곳 | 읽기/쓰기 |
|---|---|---|---|---|
| 1 | saebom_project_search | 현장 찾기(코드·현장명·고객명, 단계) | mcp.v_project | 읽기 |
| 2 | saebom_project_detail | 현장 한 건 + 남은 일정 | mcp.v_project, mcp.v_deadline | 읽기 |
| 3 | saebom_customer_search | 고객 찾기(현장 수·첫 거래일, 연락처 없음) | mcp.v_customer | 읽기 |
| 4 | saebom_deadline_list | 다가오는/지난 미완료 일정 | mcp.v_deadline | 읽기 |
| 5 | saebom_next_project_code | 다음 현장 코드 미리보기(예약 아님) | mcp.peek_next_project_code() | 읽기 |
| 6 | saebom_manual_find | 매뉴얼에서 대목 찾기 | 저장소 폴더 | 읽기 |
| 7 | saebom_manual_read | 매뉴얼 한 건 전문 | 저장소 폴더 | 읽기 |
| 8 | saebom_project_create | 새 현장 견적 등록(미리보기→승인→confirm) | mcp.create_project() | **쓰기, 기본 꺼짐** |

## 5. 자주 나오는 업종별 도구 후보

출발점으로만 쓴다. 실제 목록은 B-1 업무 질문에서 나온다.

| 업종 | 후보 |
|---|---|
| 법률·특허 사무소 | 사건 찾기/상세, 기한 목록, 의뢰인 찾기(연락처 없음), 다음 관리번호, 업무 매뉴얼 찾기/읽기, (쓰기) 사건 등록 |
| 제조·유통 | 주문 찾기/상세, 재고 조회, 출고 예정 목록, 거래처 찾기, 작업 표준서 찾기/읽기 |
| 병·의원 | ⚠ 환자 정보는 원칙적으로 열지 않는다. 예약 현황(이름 가림), 장비 점검 일정, 진료 지침 문서 |
| 학원·교육 | 반·수강생 수, 수업 일정, 미납 건수(이름 가림), 운영 규정 문서 |
| 건설·인테리어 | 현장 찾기/상세, 일정·자재 마감, 고객 찾기, 시공 매뉴얼 |
