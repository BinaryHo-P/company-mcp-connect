# 회사 시스템을 Claude 에 연결하기 (MCP)

## 이 스킬의 생각

1. **새 프로그램을 만들지 않는다.** 회사에는 이미 DB 와 파일 저장소가 있다. 그 위에 얇은 MCP 서버 하나를 얹어 Claude 가 "정해 둔 질문"만 하게 한다. 새 웹페이지·챗봇 화면을 만드는 것보다 작고, 직원은 익숙한 Claude 창에서 묻는다.
2. **AI 가 볼 수 있는 것과 할 수 있는 것은 회사가 정한다.** 그 결정이 코드 세 곳에 박힌다.
   - **도구 목록**(`tools.ts`) — 할 수 있는 일의 전부. "아무 SQL 이나 실행" 도구는 만들지 않는다.
   - **DB 뷰와 권한 축소 롤** — 볼 수 있는 칸의 전부. 연락처·금액·비공개 건 이름은 뷰에서 뺀다/가린다.
   - **쓰기 잠금** — 쓰기는 기본 꺼짐, 켜도 미리보기 → 사람 승인 → `confirm=true` → 중복 방지 원장.
3. **안전장치는 "서버가 뜨지 않는 것"으로 작동한다.** 관리자 계정으로 붙거나, 원본 표가 읽히거나, 기록자 없이 쓰기를 켜면 경고가 아니라 기동 거부다. 반쯤 열린 채로 일하지 않는다.

이 스킬을 쓰는 사람은 대개 **개발자가 아닌 대표·실무 책임자**다. 전문 용어는 처음 나올 때 한 줄로 풀고("뷰 = 원본 표에서 보여 줄 칸만 골라 만든 창"), 결정은 그 사람에게 맡기되 권장안을 먼저 말한다.

## 진행 순서

여섯 단계를 차례로 간다. 각 단계 끝에 결과를 보여 주고 확인을 받은 뒤 다음으로 넘어간다. 사용자가 이미 답을 준 항목은 다시 묻지 않는다.

### 1단계 — 질문하기

`references/design-process.md` 의 「1. 질문지」를 읽고 다섯 묶음을 묻는다. 한 번에 다 쏟지 말고 2~3개씩, 고를 수 있는 질문은 선택지로(AskUserQuestion 이 있으면 사용).

1. **시스템**: DB 종류(PostgreSQL·MySQL·SQL Server), 어디에 있나(내 PC·사내 서버·GCP·AWS·Azure), 문서는 어디에(GCS·S3·Azure Blob·공유 폴더·없음)
2. **업무 질문**: 직원이 Claude 에게 실제로 물을 문장 5~10개 ("이번 주 마감 뭐 있어?")
3. **가릴 것**: 절대 보여 주면 안 되는 칸(연락처·주민번호·금액·급여), 조건부로 가릴 것(계약 전 건 이름)
4. **쓰기**: 쓰기가 필요한가, 필요하면 어떤 한 가지(등록? 상태 변경?) — 기본 권장은 "처음엔 읽기만"
5. **사람과 환경**: 누가 쓰나(대표 혼자·팀), 쓰는 PC 운영체제, Claude Code 인지 Claude Desktop 인지, 기술 담당자가 있나

스택은 추측하지 않는다. 사용자가 모르면 "DB 관리 화면 주소나 회사 시스템을 만든 업체에 물어볼 질문"을 적어 준다.

### 2단계 — 도구 목록 초안

`references/design-process.md` 「2. 도구 설계 원칙」「3. 초안 양식」을 따라 표로 제안한다. 업무 질문 하나하나가 어느 도구로 답해지는지 연결해 보여 준다. 도구는 5~10개가 적당하다(많으면 Claude 가 고르기 어렵고, 열린 표면이 넓어진다).

### 3단계 — 보안 체크리스트

`references/security-checklist.md` 를 읽고 이 회사에 해당하는 항목을 채운 체크리스트를 보여 준다. 특히 다음은 반드시 결정을 받는다: 접속 계정 방식(클라우드 IAM vs 비밀번호 롤), 가릴 칸 목록, 쓰기 여부, 감사 로그 보관 위치.

### 4단계 — 서버 코드 만들기

1. `templates/server/` 를 사용자가 정한 폴더로 통째로 복사한다(회사 저장소 안 `mcp/` 또는 새 폴더).
2. `references/adapters.md` 에서 해당 DB·저장소·인증 절을 읽고, 필요한 선택 패키지를 설치한다(`npm install mysql2` 등).
3. **DB 쪽 준비 SQL** 을 만든다: `templates/server/sql/<DB>/demo.sql` 의 ②~④(뷰 · 쓰기 함수 · 권한 축소 롤)를 **회사 표 이름에 맞춰** 새로 쓴다. ①(가상 표·데이터)은 회사 DB 에 넣지 않는다. 회사 DB 에 실행하는 일은 사용자(또는 DB 담당자)가 시험용 DB 에서 먼저 한다.
4. `src/tools.ts` 를 2단계에서 확정한 도구 목록으로 고친다: `PREFIX` 를 회사 약칭으로, SQL 의 뷰·칸 이름을 3번의 뷰로, description 에 실제 업무 질문을 넣는다. 감사(`audited`)·가림(`redact`)·쓰기 게이트 구조는 그대로 둔다.
5. `.env.example` 을 `.env` 로 복사해 채우게 안내한다. 비밀번호는 Claude 설정이 아니라 이 파일에만 둔다.
6. `npm install && npm run build`

회사 고유 정보(실제 표 이름·고객 데이터)는 사용자의 폴더에만 쓴다. 스킬 폴더 안의 파일은 고치지 않는다.

### 5단계 — Claude 에 등록

`references/register-and-test.md` 「등록」을 따른다. Claude Code 는 `claude mcp add`, Claude Desktop 은 설정 파일(`claude_desktop_config.json`). 비밀번호 인증이면 `--env-file` 로 `.env` 를 읽게 하고, 클라우드 인증이면 먼저 로그인 명령(`gcloud auth application-default login` 등)을 사용자가 직접 실행하게 한다 — 브라우저 로그인은 사용자 몫이다.

### 6단계 — 시험

`references/register-and-test.md` 「시험 순서」를 위에서부터 진행한다. 핵심은 세 겹이다.
1. **스모크 시험**(`npm run smoke`) — 도구 목록이 나오고 읽기 도구가 답하는가
2. **안전장치 시험** — 관리자 계정으로 띄우면 거절되는가, 가린 칸이 정말 안 나오는가, `../` 경로가 막히는가, 쓰기를 confirm 없이 부르면 미리보기만 하는가
3. **Claude 에서 실제 질문** — 1단계의 업무 질문을 그대로 던져 맞는 도구를 고르는지, 0건을 지어내지 않는지

시험 결과는 통과·실패·**미시험**으로 나눠 보고한다. 실제 계정 없이 확인하지 못한 것(클라우드 접속 등)은 "미시험"이라고 분명히 적는다.

## 하지 말 것

- 운영 DB 에서 처음 시험하지 않는다. 시험용 DB(또는 `demo.sql` 로 만든 가상 DB)에서 먼저 통과시킨다.
- 관리자·소유자 계정을 MCP 접속 계정으로 쓰지 않는다(서버가 거절하도록 만들어 두었다 — 이 검사를 끄지 않는다).
- "아무 SQL 실행", "아무 파일 읽기" 같은 만능 도구를 만들지 않는다.
- 비밀번호·키를 Claude 설정 파일, 대화, 코드에 적지 않는다.
- 사용자의 실제 고객 데이터를 예시·문서·시험 데이터에 옮겨 적지 않는다.
- 클라우드 IAM 설정(`gcloud ... add-iam-policy-binding` 등)이나 DB 플래그 변경처럼 운영에 영향이 있는 명령은 대신 실행하지 않는다. 명령을 적어 주고, 영향(재시작·권한 범위)을 설명한 뒤 사용자가 실행하게 한다.
